# Java 1.20.1 知识库

`knowledge/minecraft-java-1.20.1/` 是随仓库维护的首批游戏资料，不是 Minecraft Wiki 全站镜像，也不代表已覆盖全部机制。它提供可以主动搜索、逐章阅读和继续追问的参考，让 Agent 了解世界规则、条件、例外与可能做法。资料可以涉及当前尚无专用技能的机制。

运行时只读本地文档：查询本身不访问网络、不执行游戏动作、不生成行动队列、不登记行为、不把文献写成个人经历或已学技能。维护者在更新资料时核对外部来源，与游戏运行中的查询是两个过程。文献不能证明当前世界存在某个资源、某个物品已经取得或某种方法已经成功。

## 查询接口

沿用心智的只读查询协议，由模型直接输出一个查询对象：

```json
{"kind":"knowledge","query":"剪过毛的羊怎样重新长毛"}
```

搜索返回相关文档、章节与短摘录；需要完整条件时，再读选中的章节：

```json
{"kind":"knowledge","id":"animal-husbandry","section":"wool"}
```

省略 `section` 可阅读该文档，空查询可以浏览目录：

```json
{"kind":"knowledge"}
```

`knowledge` 查游戏资料，也可读取 `agent-controls` 操作手册：它按当前注册接口生成，标记为 `control`，包含接口原有的参数、说明和时限，涵盖基础操作及已有复合动作，不把它们称为 Agent 自学成果。`moves` / `mechanics` 仍可查实际动作接口，`recipes` 查本版本配方和缺口，`recall` 查自己的经历。这些来源的含义保持独立。

搜索结合标题、章节、中文词组、英文名称和别名匹配，默认返回 4 段、最多 5 段，每段不超过 700 字符；正文总计最多返回 4,200 字符，截断处标记 `truncated`，其余章节用 `nextSection` 提示，可以指定章节继续阅读。目录默认列出 12 篇，可按返回的 `nextOffset` 再传 `offset` 翻页；查询与现有工具共用每次思考 3 次的预算。返回完整 JSON，不截断序列化后的对象。

查不到意味着本地首批资料没有匹配结果，不代表游戏不存在这种机制；可以换用实体名、物品 ID、中文别名或相邻概念继续查。正文在启动时读取并建立内存索引，更新文件后重启 Agent 生效；没有在线抓取或自动更新，也不需要新依赖或独立数据库。

## 文档格式

每篇一个 UTF-8 Markdown 文件，文件名与稳定的 `id` 一致。开头两行 `---` 之间是受限元数据：每行 `key: JSON值`，**不是 YAML**。字符串、数组和对象均使用合法 JSON，不写 YAML 缩进对象、多行字符串或注释。

```markdown
---
id: "example-mechanic"
title: "示例机制"
kind: "mechanic"
edition: "java"
versions: ["1.20.1"]
aliases: ["中文别名", "item_id", "English name"]
sources: [{"url":"https://minecraft.wiki/w/Example","title":"来源标题"}]
versionNote: "说明已核对的适用范围、排除内容与仍未确认的部分。"
reviewedAt: "2026-10-28"
---

## conditions | 条件与例外

说明机制何时成立、需要什么以及不成立的情形，在相关事实旁标注来源链接。

## effects | 产生什么结果

区分规则预期、实际观测和物资取得。
```

`kind` 使用 `mechanic` 或 `tutorial`。前者说明规则，后者说明一种可选做法与适用条件，不能把攻略写成 Agent 必须遵循的主线。每篇采用少量语义完整的短章节，每节控制在 4,200 字符以内，确保能单独读全；`section-id` 使用稳定的小写字母、数字和连字符，标题保留用户可读的中文。相关条目可写成 `[羊毛再生](knowledge:animal-husbandry#wool)`，保持目标文档与章节真实存在。

别名可以包含中文说法、英文名称和游戏 ID，服务于用户实际提问；不要用与正文无关的热词增加匹配。新增章节应独立读得懂，保留前提、例外和必要的版本限制，不依赖把全文同时塞入上下文。

## 来源与版本维护

- 本目录只声明 `edition: "java"`、`versions: ["1.20.1"]`。当前 Wiki 页面往往同时描述最新版、Bedrock 和历史变化；需要核对具体机制在 Java 1.20.1 是否成立，不能给当前网页贴一个版本标签就当作核对完毕。
- 每篇保留来源标题和原始页面 URL，正文使用原创释义并在事实旁链接来源。对教程保留可选性与代价，不大段复制原文；引用图片、转载正文或导入整站资料需要另行核对相应来源与许可。
- `sources[].revision` 可填确实取得的来源修订标识；不知道就省略，不能编造，也不能用 Minecraft 版本号代替。`reviewedAt` 是维护者核对日期，不是来源发布日期或内容快照。首批文档没有固定来源修订号。
- 来源页面修订号只标识文献快照，不自动证明其中每条规则适用 1.20.1。对后续改动、实验开关、服务端数据包或模组影响，在 `versionNote` 与相关章节明确说明。未知的适用性不能写成“已验证”；不能核实的精确数字、概率与配方先不收录。
- 更新文档时检查同篇其他章节与内部链接。不要将查阅日期、现场失败原因或个人试验结果混进普遍机制；有意记录经验时，走经验与技能的独立记录流程。

添加资料后的基本检查是：元数据各值能被 JSON 解析，文档 ID 与章节 ID 不重复，来源可追溯，内部链接存在，搜索能按中英文常用词找到相应章节。版本边界、游戏规则与程序接口的区别应通过内容审查确认。
