# 身体接口与执行授权

本接口面向 Minecraft Java 1.20.1。操作目录由实际技能注册表生成；查询到接口或规则，不代表当前世界已有资源或已经验证掌握。

## 准备工作

所有技能共享 `make` 参数。默认不额外制造工具、中间材料或准备设施；缺少条件时返回缺口。

- `make:true`：允许该动作的准备辅助消耗材料，例如合成前置材料、制作和放置工作台或熔炉。结果仍须核对实际产出和资源消耗。
- `make:false`：该动作及其嵌套技能都不能开启准备。
- 明确调用 `craft` 可以合成本次指定的目标物品；缺少前置材料或工作台时，默认不会另行制作或放置。

例如，`craft {"item":"wooden_pickaxe","make":true}` 允许准备工作台、木板和木棍；省略 `make` 时须先自行准备。`dig_at` 默认只使用已有工具或空手挖掘。

## 选择具体物品

`inspect_inventory {}` 返回每个占用槽的编号、名称、数量、耐久、附魔、自定义名称和简化 NBT。药水类型、书本页、作者和地图 ID 可从 NBT 读取，同名物品不会在此接口合并。

```json
{"skill":"hold_item","args":{"item":"diamond_pickaxe","sourceSlot":9}}
{"skill":"hold_item","args":{"item":"diamond_pickaxe","sourceSlot":9,"slot":2}}
{"skill":"hold_item","args":{"item":null,"to":"off-hand"}}
{"skill":"toss_item","args":{"item":"potion","sourceSlot":12,"count":1}}
```

`sourceSlot` 是玩家物品栏源槽（5–45），`slot` 是目标快捷栏（0–8）。指定源槽后，源物品已改变或消失会返回失败，不会改选另一叠。空手或卸甲不授权丢弃物品；背包放不下时返回失败。使用同名物品时保留已明确拿在手中的那件。

挖掘时，如果当前手持物品有耐久、不能加快挖掘，且没有更合适的已有工具，身体会切换到背包中已有的非耐久物品（如泥土、圆石），确认换手后再挖；切换不会放置或消耗该物品。没有这类物品时才尝试腾空主手。若没有空槽或换手未确认，则停止本次挖掘并返回原因，不能用丢弃物品来腾空主手。

## 界面和文本

`use_gui` 可打开可见方块、`{"entityId":23}` 指定的可见实体容器，或 `"inventory"` 自己的物品栏。打开坐骑背包前须先骑上该坐骑。返回本次窗口槽位、物品属性及鼠标光标。

- `put.sourceSlot` 使用**本次窗口**显示的源槽号；它与玩家物品栏槽号可能不同。
- `click` 支持 mode 0 普通点击、1 shift 点击、2 快捷栏交换（button 0–8）、3 创造模式克隆、4 丢弃。实际游戏模式仍决定操作能否生效。
- 库尚未实现的拖拽、双击和 button 40 副手交换会明确拒绝；相同物品移动可用普通槽位点击组合。
- `rename` 只确认铁砧产物的名称预览；取出产物才完成改名。
- `beacon` 指定 `primary` / `secondary` 效果 ID 或 null；只在支付消耗得到确认后报告接受，身体是否受到效果需另查状态。

每次调用按 `ops` 顺序操作并关闭窗口；输入是否退回由具体界面的游戏规则决定。点击后的槽位和光标会与服务器同步，不能将客户端预测当作成功。

`sign_text {"target":{"x":2,"y":64,"z":0}}` 读取当前可见告示牌；提供 `lines` 写入，`back:true` 选择背面。编辑须得到服务器开启编辑器和实际文字回执；玩家仍需位于能够编辑对应一面的地方。

`edit_book {"sourceSlot":9,"pages":["第一页"]}` 编辑书与笔；显式提供 `title` 会签名为不可再编辑的成书。读取现有内容使用 `inspect_inventory`。写入仅以服务器返回的物品 NBT 确认。

## 桶与原始使用

`use_item {"item":"water_bucket","on":{"x":2,"y":64,"z":0}}` 将坐标解释为目标流体格；`lava_bucket` 同理。当前定点接口只支持空气格及其相邻可点击的实心参照面，不隐式移动、搭块或改选目标。水桶会填入参照块自身的未含水面不用于定点倒水；原始使用入口仍可操作该类方块。发出使用输入前核对命中方块与命中面；同步期间站位或视线变化使实际射线不再匹配时停止，返回事实。

一次倒桶只发送一次使用输入，在有界确认窗口内等待满桶减少、空桶增加、指定格出现对应源状态。消息先后顺序不改变验收标准；只确认部分变化时保留部分事实，返回 `PLACEMENT_NOT_CONFIRMED`，不会为等待消息而重复倒桶。缺参照面、没有可点击面、未见效果分别保留 `NO_REFERENCE`、`NO_PLACEMENT_FACE`、`NO_EFFECT`。

`use_item {"item":"bucket","on":{"x":2,"y":64,"z":0}}` 精确收集当前可见、可触及的独立水源或熔岩源。旧会话、其他维度、过期观察或未知源状态不能作为交互依据；适配器进一步确认实际射线首先命中所指定的源。成功以空桶减少和对应满桶增加确认，源格重新生成或被流水填回不抵消已经发生的取水。动作后的源格只通过当前观察报告，看不见则为未知。

`use_item {"item":"bucket","on":"water"}` 是按名称在可见流体源范围内选源：辅助可在范围内选择并报告实际对象，仍只取独立源（level=0）。与精确坐标不同，名称调用不锁定单一格；侧面可接触、顶部有遮挡的源同样可选，源格顶部有无遮挡由交互射线确认命中，不在选源时排除。放船（`*_boat`/`*_raft`）对 `on:"water"` 才要求“上面是空气”的开阔水面，与空桶收集条件分开。

`use_item {"item":"fishing_rod","on":"self"}` 是沿当前准星使用的原始入口，不自动低头、选点或切换目标。`inputCompleted:true` 表示使用输入已完成；`effectEvidence` 单独描述已确认的效果。数量未变不使这种原始输入失败，也不证明鱼竿或其他工具没有生效。桶需完整容器转换才确认相关库存效果，无关拾取不能证明用桶成功；即使转换已确认，`self` 也不承诺放置位置。技能层保留“输入完成、效果未知”，不将其计为已验证成功，也不等同于没有执行。

## 水中移动与换气

水里怎么动、往哪游由 Agent 决定；以下动作分别承担稳定执行的一部分，不自动升级成找岸、挖气穴或救援流程。

- `surface {}` 只做一次有界上浮：按住上浮让头露出流体换气，不找岸、不找气穴、不挖不垫、不改目标。结果区分 `surfaced`（结束时头已露出流体、进入空气）与 `landed`（站稳干地）：浮出水面不等于上岸，`surfaced` 只确认结束时头在空气里，不保证松开控制后继续浮着或持续换气。可选 `{"timeoutMs":毫秒}`（1000–20000）限定本次上浮时长。它不再接受旧的 `escape:"dig"|"shore"` 参数，传了会明确拒绝。
- `swim_to {"xyz":[x,y,z]}` 从当前位置朝调用方指定的世界坐标游过去（`xyz` 是游过去后脚所在的世界坐标，可含小数/负值，原样传给底层、不改写不取整），保持这一个目标不换；站在干岸上也会先走进水里再游，不是寻路；到目标附近站稳（干地）才算到，否则如实报告位置、氧气与未到原因。可选 `{"timeoutMs":毫秒}`（1000–20000）。
- `dive {"xyz":[x,y,z],"min_oxygen":n}` 在水里朝一格游过去（往下潜或往上游），气降到 `min_oxygen` 就停下回报。
- `press_keys {"keys":{"jump":true},"ms":n}` 按住上浮键一段有界时间后松开，是最原始的有界上浮入口，不自动确认换气。
- `dig_at` 仍是独立的挖掘动作：要挖开头顶封住的方块时由 Agent 显式选择，`surface` 不会代挖。

浮出水面（`surfaced`）只确认结束时头离开流体、进入空气；头在实心方块里不等于能呼吸，岩浆不算流体之外的干地。是否上岸（`landed`）、是否继续游向某处、要不要挖开头顶，仍由 Agent 按实际目标决定。氧气数值本身不能证明已经浮出水面。

## 风险和学习证据

`dig` / `dig_at` 对邻接液体默认停止。`wet:true` 明确接受进水，`lava:true` 明确接受进岩浆，两项权限分别生效；进水或进入岩浆后的行动由 Agent 或其学会的技能决定。长时间空手挖掘受动作预算限制，会报告时间限制而非游戏规则禁止。

`dig_at` 的 `fall:true` 显式接受移除脚下支撑后的坠落风险，独立于 `wet/lava`。`api.digAt(x,y,z,{fall:true})` 与 `api.act("dig_at",{...,fall:true})` 均传递这项授权；steps/code 嵌套恢复不得擅自增加它。结果保留当前观察支持的风险事实，隐藏落点和实际落差未知时不补造答案。

从经历提取的动作链只成为候选；保留原目标、数量与开关，实际试用并通过结果验收后才晋升。死亡事实、游戏播报和状态推测分别记录，不把程序固定建议写成亲历经验。
