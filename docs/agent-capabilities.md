# Agent 能力与验证

本实现对应 [自主玩家路线图](agent-evolution-roadmap.md)。M0–M6 表示能力建设范围，运行时不按阶段强制派发玩法。模型可以继续种田、欣赏风景、装修、暂缓或放弃自己的兴趣。

## 当前接口

| 范围 | 实现 | 结果语义 |
|---|---|---|
| M0 | 统一暂停、异步代次、动作所有权、内部异步取消、观测就绪、世界/维度/会话隔离、环境逃生 | 用户暂停也禁止反射；过期回复在记忆副作用前丢弃；未知观测不能验收；短暂露头和恢复氧气不等于上岸 |
| M1 | `Intent`、`Preference`、`Decision`、单主动项目、顺序里程碑、恢复检查点 | 模型选择继续/改法/改意/暂缓/放弃；主观结束与事实完成分开 |
| M2 | `BuildingSpec`、可组合部件、旋转、逐格材料/状态、勘察/地基/脚手架、续建/修复 | 必需格和功能全部通过才能完工；脚手架拆除也是验收项；取消后重新观察待确认放置 |
| M3 | 版本匹配配方查询、物资预留、能力缺口、参数化 DSL、隔离试验、版本晋升/退役 | 注册的候选仍未验证；两个独立试验情境的状态证据才能晋升；未知超时不盲目重复合成 |
| M4 | 作品版本、成对比较、回退、用户/模型反馈、固定机位观察、语义色 PNG | 外观判断是主观评价；PNG来自实际视觉射线，不能用于声称看见原版材质细节 |
| M5 | 多命名基地、首选基地、建门/点火、实测两端门户、可靠返程记录 | 不按坐标比例猜出口；反向实际穿越后才标记返程已验证 |
| M6 | 末影之眼轨迹搜索、既有末地门激活、护甲/远程战斗、龙阶段控制、末地折跃门 | 下降眼迹只是线索；没有看到门框不能声称找到门室；目标消失不等于击败龙 |

精确事实条件是 `inventory_min`、`location_near` 和 `all_of`。验收使用同一次完整 `adapter.state()`；箱子历史快照、提示词截断背包、预期掉落和技能的成功文字均不能代替当前持有事实。里程碑证据保留历史含义，最终条件另行读取当前状态。

连续三次实际无进展尝试触发阻塞并请求模型重新选择。等待网络、暂停和反射打断不消耗该预算。真实 LLM 超时或超预算时保留意图与证据，等待下一次有效决策；`mock` 是显式兼容模式，其规则行动不能算自主能力证明。

## 使用

```powershell
npm start
```

控制台展示当前意图、缘由、最近选择、项目状态和实际证据。`!goal` 仍是建议；`!pause`、`!resume`、`!replan` 保持控制语义。

默认会在模型决策正式生效时，把 AI 的简短角色独白写入服务器聊天，便于 ServerReplay 捕捉，例如 `[想法] 我有点好奇，这棵树另一侧的轮廓是什么样。`。内容来自 `thought`，表达当前感受、好奇或疑惑；不再播报行动计划、技能开始/结束及结果，也不另发 `say`。排队中的预规划、规则模拟和填充行为不广播；没有想法时保持安静；用户暂停、死亡和断线清除待发字幕。沿用 `CHAT_ACTIONS=false` 关闭，`CHAT_ACTION_INTERVAL_MS=1800` 调整最小间隔。

- `!prefer 喜欢在同一个地方慢慢经营`：保存用户明确偏好。
- `!feedback <作品 ID> 门廊让我觉得太拥挤`：保存用户作品反馈。

暂缓的兴趣不会自动变成失败或被另一条主线替代。模型可以用 `begin` 引用已有 `intentId`，恢复原项目 ID、规格修订、里程碑和检查点。另一个世界的项目可以保留，但不能继续绑定当前世界的动作或验收。

常用新增工具：`building_archive`、`building_review`、`query_resource`、`material_reservations`、`method_catalog`、`record_ability_gap`、`base_memory`、`build_portal`、`observe_portal`、`travel_portal`、`recall_portal`、`activate_end_portal`、`equip_armor`、`ranged_defend`、`find_stronghold`、`dragon_fight`、`use_end_gateway`。参数以当前技能目录为准。知识和档案查询不消耗物理项目的无进展次数。

## 配置与记录

| 配置 | 默认 | 用途 |
|---|---|---|
| `LLM_MAX_PROMPT_TOKENS` | `128000` | 整个序列化上下文的保守 UTF-8 字节上界，包含元数据、记忆、重试及工具返回；它不是精确分词计数 |
| `LLM_MAX_TOKENS` | `16384` | API 的实际输出 token 上限，推理型模型可能把思考计入其中 |
| `LLM_TIMEOUT_MS` | `120000` | 请求超时，给推理与长输出留出时间 |
| `LLM_CONTEXT_WINDOW_TOKENS` | `1000000` | 模型上下文容量配置；用作单次请求预算的上界，并为输出预留空间 |
| `LEARNING_TEST_WORLD_IDS` | 空 | 可为候选方法提供晋升证据的独立试验世界 ID，逗号分隔；模型不能自行宣称当前世界已隔离 |
| `CHAT_ACTIONS` | `true` | 将 AI 的简短想法写到游戏聊天，供 ServerReplay 捕捉（沿用原配置名） |
| `CHAT_ACTION_INTERVAL_MS` | `1800` | 聊天播报最小间隔；超过十秒的待发内容会丢弃 |

每次规划重新组装当下状态、当前兴趣/项目、偏好与必要证据，不携带上一轮模型对话。记忆服务只在模型主动请求 `recall` 时查询；当前意图和用户偏好仍作为少量必要摘要。一次决策内最多两轮回想与有限格式修正，请求结束即释放这些对话。压缩会保留当前失败、项目绑定、当前里程碑和实际验收条件，优先减少历史细节与重复描述；技能名及参数格式保持可用。准备请求前后让出事件循环，历史记录按条编码，避免反复序列化整个记忆列表。

意图、项目和证据随 `world-memory.json` 保存。作品、物资预留、门户和方法分别保存到 `building-artifacts.json`、`material-reservations.json`、`travel-memory.json`、`method-library.json`；图片在 `building-views/`。全部位于 `DATA_DIR`，由 `memory:clear` 的整个数据目录清理覆盖。外部记忆的配置和清空见 [Hindsight 文档](memory-hindsight.md)。

`learn_skill` 接受有界 `call / sequence / if / repeat` 程序和有限参数，以及可观测 `postcondition`，不执行任意 JavaScript。候选名称为 `trial:<name>:vN`，通过试验晋升后为 `method:<name>`。已有成功版本可在后续版本退役时恢复。

## 验证

```powershell
npm run typecheck
npm test
```

定向测试覆盖意图/项目、恢复与迟到回复、预留保护、方法试验、建筑验收、方块状态协议、视觉、门户/返程、装备、末影龙/结构以及实际配方的背包同步。

真实评审脚本只用于另行准备的独立存档：

```powershell
$env:DATA_DIR = '.roadmap-validation/live'
$env:AGENT_REVIEW_PORT = '25585'
$env:AGENT_REVIEW_SECONDS = '55'
npx tsx scripts/review-agent.ts
npx tsx scripts/check-craft-live.ts
```

`review-agent.ts` 使用真实 LLM，记录模型输入/输出、选择、实际动作、失败和最终观测到 `DATA_DIR/reviews/`；它会把测试上下文发送到配置的 LLM 服务并产生测试世界动作。`check-craft-live.ts` 只使用该测试角色已有背包验证合成，不调用 LLM 或管理指令。建筑定向夹具可用 `scripts/check-building-runtime.ts`。

本次实机检查已揭示并修复嵌套意图格式、合成背包同步、共享原料复查和工作台选址问题。已在独立 Minecraft 1.20.1 存档中实际合成木镐。开放游玩评审已经运行，记录包含模型自选兴趣及未完成尝试；不能把短时试跑等同完整自主性结论。

房屋实测从中断检查点续建，通过全部 150 项逐格与功能检查，门、窗和阶梯坡顶均在真实世界中确认；13 个临时脚手架已拆除，四个固定视角观察及 PNG 已保存。放置寻路需要在实际眼位核对可点击面，失败时有界更换站位；高处施工明确使用已记录的脚手架入口。

水中脱困会持续上浮并在保持浮力时观察、转向，朝实际看见且重新确认有支撑与头部空间的岸边游动。只有离水、站稳且氧气恢复才报告上岸；没有岸边证据则明确失败，不反复把氧气 13–14 时的短暂露头称为成功。四格深水实机已上岸，释放控制三秒后仍为干地/onGround/氧气 20。避难坑已修正为挖三格、在原地表层封顶，逐层确认真实落地；真实服务器验证两格头部空间且没有身体碰撞。

下界执行链已通过三个独立种子的真实建门、自然材料采集和带材料返程，见[三种子复验记录](portal-runtime-validation.md)；该测试不调用 LLM，与自主目标选择评审分开。末地通关和完整 Boss 战在至少三个独立种子中的专项实机验收仍未完成。高塔、笼装水晶、龙的近战几何，以及复杂地形建筑不能仅凭离线夹具宣称稳定成功。原版材质级视觉审美仍需更丰富的实际图像源；当前图像明确为语义色射线图。
