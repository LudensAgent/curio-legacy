# 行为技能、专注与回想

## 行为技能（会动手的技能）

技能书（`skills/` 内置、`data/skills/` 自己写的）里的一份技能，正文里带一段 ```` ```behavior ```` JSON 时，就是身体真的会去做的技能：

| when | 模式 | 身体怎么用 |
| --- | --- | --- |
| 含 `after_failure` | recover | 活动里某个动作失败时先照它做；未观察到实际动作效果则换其他恢复技能或交还心智，否则再重做失败的那一步 |
| 只有状态条件 | auto | 条件成立就由反射层接手（`use_skill`，来源 reflex），可以用 `overrides` 换掉某个本能 |
| 不写 | manual | 只在 routine 里 `use_skill {"name":…}` 调用 |

- 模型写 `skill` 新建/修订后先存 `data/skills/<name>/candidate.json`。Agent 用 `use_skill {"name":"…","trial":true}` 显式试用；候选不参与自动/恢复调度，稳定版继续使用。当前候选至少三次实际验收成功、且成功不少于失败的两倍才晋级为 `SKILL.md`/`code.js`。跳过和无动作自报成功不算成功证据。
- 停用与收起同时约束调度、直接调用和后台结果写回；心智显式修订可试用新候选，但旧停用版不会提前复活。合并候选验收前保留来源技能。手动和嵌套调用均记录真实版本和使用时间。
- 条件只能描述身体感觉得到的事（`src/mind/predicate.ts`）：血量、饥饿、氧气、水/岩浆/地面/昼夜/明暗、看见或听见的敌对生物、背包、正在做的动作、以脚为原点的身边方块、刚失败的动作和失败码。
- 每次使用记成败（`data/skill-stats.json`）；自己写的技能用了 4 次以上成功率不到 1/4 会被停用，并作为“注意到的事”提醒心智去改。
- 代码里的反射保留为有名字的“本能”（`INSTINCTS`）；技能可用 `overrides` 声明代替。`lava`、`drowning` 保留为兼容名称，代码没有自动接管，相关条件和行动可由技能自己决定。
  - 现在运行时用的是 `instincts: 'skills'`：躲苦力怕、低血逃、还手、夜里挖坑这几条代码里没开，靠自己写的技能。哪些开着由 `Reflex.activeInstincts()` 决定，心智（`body_instincts`）和写技能的模型（`instinctNote()`）看到的是同一份如实的清单。
  - 救命的技能（`isEmergency`：自动/恢复类、条件里有掉血/挨打/怪/窒息/溺水/岩浆，或换掉某个本能）平时很少触发：整理时不按“好久没用”“技能太多”收起，只在一再失败时收。
- 刚卡住、随后在同一带做成另一段活时，下一次思考会收到提醒：把这次管用的做法写成技能。

### 技能书一开始是空的

仓库的 `skills/` 只留两份说明：`writing-skills`（怎么写技能）和 `architect`（建筑师的设计手册）。不预置任何会动手的技能，也不预置做法说明：躲怪、逃跑、还手、脱困、寻路恢复、安家……都由它在游戏里碰到之后自己总结成技能。

当前运行模式不把遇到岩浆、低氧时的行动写成强制反射；条件和应对由 Agent 自己或其技能决定。卡死检测和可配置的 habits 仍会运行。

以前内置的几份示范技能（局部 A* 寻路、受伤撤退、躲苦力怕、还手、饿了吃、垫高出坑、迈上土坎、安家）挪到了 `tests/fixtures/skills/`，只用来测试机制。

- 触发条件里可以用 `hurt_within`（最近几秒挨过打）和 `cover`（sealed 封好的坑 / pit 坑里 / open 空地）。
- 自动技能的成败不看它跑没跑完，而是 **12 秒后看结果**：死了或又掉了 6 点以上的血就记一次没用，记录里带着触发时的血量、周围的怪、掩体、当时在做什么，后台改进器拿着这些去改代码。技能自己判断不用做时返回 `skipped`，不计数。
- `Reflex` 的旧写法（代码里的躲苦力怕、逃跑、还手）仍保留在 `instincts: 'builtin'` 模式里给测试和兼容用；`main.ts` 用的是 `instincts: 'skills'`。

### 代码技能

`steps` 写不出的做法（寻路算法、按地形挑落脚点、绕着怪走……）由模型直接写成 JavaScript（`"code"`），存成 `data/skills/<name>/code.js`，写下就能被调用：

- **运行**：`use_skill` 把代码放进独立的工作线程（`src/codeskills/sandbox-worker.mjs`），线程里再用无原型的 vm 上下文隔开，禁止 eval/new Function，和 vm 之间只传字符串。代码只能通过 `api.*` 碰游戏（`src/codeskills/bridge.ts`）：状态、身边 48 格内的方块/区域、看见听见的生物、迈一格/挖/放、寻路、调用已有动作。一段同步计算超过 1.5 秒（死循环）就终止线程；另有总时限和 4000 次 api 调用上限。（在主线程里用 vm 超时打断会弄坏 Node 的异步上下文，所以必须是独立线程。）
- **出错信息**：失败时带回出错的行号、最后 30 次 api 调用和 `api.log` 的内容，记进技能的运行记录。
- **自己变好**：`CodeImprover` 用实际记录修订同名完整契约（代码/步骤、参数、触发、验收），先保存候选。静态检查能发现未定义变量和未知 API，但不能证明玩法有效；空正文、截断和过期回复属于生成失败，不计游戏失败。`versions/vN.json` 保留完整旧契约，回退不再只换代码；缺少完整快照的旧版本不能冒充完整恢复。心智仍可主动要求改进。
- **感知边界**：代码与验收共用当前视觉读取；未观察方块的名称和几何都为 unknown，不能透视矿物或地图。听觉只给粗略方位/距离，精确实体动作要求 seen。所有操作仍经已有动作元语与原有取消、时限和物理约束；不开放宿主 adapter、网络或文件接口。
- **不会太频繁**：同一时间只改一份；两次改进至少隔 `SKILL_IMPROVE_GAP_MIN`（默认 20 分钟）；同一份技能 60 分钟内（主动要求时 30 分钟）只改一次；每小时最多 2 次。

完整写法见 `skills/writing-skills/SKILL.md`（模型可以 `{"kind":"skill","name":"writing-skills"}` 翻开）。

## 专注

- 主目标（议程里 active 的一项，只能是 goal，点子和疑问不能当主目标）配一份清单 `plan`：`{"focus":"a_…或一句话","steps":[…]}`，做完一项 `{"done":[序号]}`；全部勾掉即主目标完成。
- 【专注】块放在用户消息靠后（模型注意力最强的位置），写明主目标、清单和当前这段活是否在推进它。
- 瞥一眼时不能 `switch`（改成 `detour`，做完自动回来）；认真想过可以换。
- 【专注】带着进展的事实：多久没勾掉一项（`no_progress_min`）、这期间做了几段活（`activities_since_progress`），原样重写清单不算推进。清单久没推进时由它自己判断这个目标还值不值得。
- 清单每一项要是动作能完成、能验证的事；看到的资源和地点会自动记住，不需要“去记坐标”这类清单项。
- 刚开工、还顺利的活，瞥一眼时的 `adjust` 排到这段做完之后。
- “快干完了想想接下来”每段活只问一次；两次“抬头看一眼”之间至少隔 `glanceGapMs`（默认 12 秒，要紧的事不受限）。

## 回想

`src/mind/recall.ts` 在本地按关键词（中文二字片段 + 英文注册名）从做过的事、日记、游戏教训、笔记、技能书和地标里挑出相关的几条：

- 每次思考前自动用“主目标 + 清单下一项 + 手上的活 + 最近的失败 + 注意到的事”想一遍，放进【想起来的】；认真想时，分数够高的技能直接翻开全文。
- 模型也可以 `{"kind":"recall","query":"关键词"}` 主动回想；接了 Hindsight 时仍走 Hindsight。

## 走路卡在脚边方块

- Pathfinder 的斜向一步只要求一侧能过，0.6 格宽的身体会被另一侧方块的角卡住：`src/adapter/corner-safe.ts` 要求两侧（脚和头的高度）都空才走斜线。
- 寻路思考上限从 5 秒放宽到 10 秒；“Took to long to decide path”按 PATH_NOT_FOUND 处理（会触发恢复类技能），不再当程序错误。
- 开始寻路时身体贴着脚边/头边的实心方块又离格子中心较远，先潜行挪回格子中心再走。

## 自我学习的闭环

| 环节 | 谁来做 | 什么时候 |
| --- | --- | --- |
| 写新技能 | 心智（决定里的 `skill`）；后台“造技能”（`src/codeskills/smith.ts`） | 心智随时；造技能见下 |
| 用 | 行为引擎：自动 / 失败时先试 / `use_skill` | 条件成立时 |
| 评 | 自动技能看 12 秒后的结果；恢复技能看重做的那一步；代码出错直接记失败 | 每次用完 |
| 改 | 后台改进器（`improver.ts`） | 代码技能当前版本失败 ≥2 次且过半；或心智要求（默认不限频） |
| 整理 | 后台整理（`curator.ts`） | 每 10 分钟检查：收起长期用不上的；有新技能或新冲突才请模型合并、调优先级 |

- **造技能什么时候学**，不写死成“卡住几次”，而是四个来源：
  - 心智自己点名：决定里写 `worth_learning`（哪里出了问题、想学会什么），后台拿前 3 分钟的经过去写。心智在当下不用写代码，只要指出值得学的地方。
  - 定期回顾：天亮时、歇下来回想时，把这段时间做过的事（最近 30 段活的结果和用时）交给后台，找反复出现、费时、常失败的问题，最多写 2 份。能抓到“每次找石头都很慢”这种不出事的慢性问题。
  - 吃亏程度（`PainMeter`）：掉血、死亡、丢东西、卡住、失败累加成“痛”，半衰期 3 分钟；每 30 秒和它自己平时的水平比（指数滑动的均值和波动），明显高出才算一次值得学的事。前期常死标准就松，后来稳了偶尔一次大亏也会被注意到。
  - 死亡：一定回头看。
- 造技能拿着经过（挨打、反射、动作、念头、死亡播报，最多 90 条）、当时的状态和现有技能一览，写一份技能或同名重写没做好的旧技能；不是技能能解决的就不写。不限次数，同一时间只写一份、其余排队（死亡和心智点名的先写），挨得很近的同类事并成一件。
- **后台写代码的模型**（造技能、改进、整理）可以单独配置：`CODER_LLM_MODEL` / `CODER_LLM_BASE_URL` / `CODER_LLM_API_KEY`，默认推理力度 high，单独的每小时预算 `CODER_LLM_MAX_CALLS_PER_HOUR`（默认 1000，基本不限）。不设模型就用主心智的模型，但仍走单独的预算和高推理力度。调用记在 `data/logs/llm-coder-*.jsonl`，也会出现在控制台的 LLM 调用页。
- **竞争**：几个自动技能同时满足条件时，按“优先级 + 40 ×（成功率 − 0.5）”挑，成功率按（成+1）/（用+2）算；谁和谁抢过记在统计里给整理用。
- **收起**不是删除：同名重写会恢复。

## 学习曲线（`src/observer/scorecard.ts`）

总分 0–100 = 进度 40% + 生存 20% + 学习 25% + 效率 15%，每 30 秒取样一次，存在 `data/scorecard.json`，控制台“学习曲线”页显示：

- **进度**：37 个里程碑，沿着原版成就的路线分组（起步、活下来、过日子、铁器、钻石、下界与末地），按权重累计、只增不减。背包里出现对应物品、游戏播报对应成就（服务器发的英文成就名，例如 [Stone Age]）、或者相应的事件和状态（活过一晚、睡觉、盖好房子、进下界/末地、种地、钓鱼）都算达成。合成后马上放下的工作台、熔炉从合成结果里认。里程碑表以外的游戏成就每个另加 1.5 分（最多 10 分）。
- **生存**：按“活了多久”走 S 形曲线 `1 / (1 + e^(−(分钟 − 20) / 6))`：刚复活几分钟几乎不得分，撑过一个游戏日（20 分钟）正好一半，40 分钟约 97%，再往后不再无限加分。当前这条命占 60%，最近 5 条已结束的命的中位数占 40%（稳定地活得久才高）。
- **学习**：用过 ≥2 次且成功率过半的技能每份 15 分（上限 60）+ 被验证过的窍门每条 4 分（上限 20）+ 技能平均成功率 × 20。
- **效率**：最近半小时动作成功率 × 70 +（1 − 卡住比例）× 30。
- **每条命的用时**：每次复活都从空手开始，记到达工作台、石镐、熔炉、火把、床、盖好房子各用了几分钟。这条最能说明有没有学会：同样的起点，越来越快。
